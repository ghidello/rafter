# Test assets

These are maintained inputs for the xUnit suite and development tools. Examples for script authors live separately
in [examples](../../examples/README.md); unchanged old-project material lives in [reference](../../reference/).

| Asset group | Callers and purpose |
| --- | --- |
| [consumers/host](consumers/host/) | [ConsumerTests](../Rafter.IntegrationTests/Consumers/ConsumerTests.cs): package-free file-app/project host checks, argument boundaries, working directories, and separate streams. |
| [consumers/runtime](consumers/runtime/) | [RuntimeConsumerTests](../Rafter.IntegrationTests/Consumers/RuntimeConsumerTests.cs) and [Windows process API consumers](../Rafter.WindowsTests/Consumers/ProcessApiConsumerTests.cs): current API checks in both hosts. Also used by [runtime terminal verification](../../tools/verification/Verify-RuntimeTerminal.ps1). |
| [processes](processes/) | [Process tests](../Rafter.WindowsTests/Processes): real child processes for quoting, output, descendants, cancellation, ownership, and failure observations. ProcessProbe is the only asset project included in the root solution. |
| [workflows](workflows/) | [ProcessConsumerTests](../Rafter.WindowsTests/Consumers/ProcessConsumerTests.cs): a library and one-test project used by the build/test examples, including deliberately failed builds/tests in isolated copies. |
| [evaluations/parser](evaluations/parser/) | [ParserTests](../Rafter.UnitTests/Evaluation/ParserTests.cs) and [ParserBaselineTests](../Rafter.UnitTests/Evaluation/ParserBaselineTests.cs): adapted/raw parser behavior. [ParserConsumerTests](../Rafter.IntegrationTests/Evaluation/ParserConsumerTests.cs) executes the real file-app probe. |
| [evaluations/renderer](evaluations/renderer/) | [RendererTests](../Rafter.UnitTests/Evaluation/RendererTests.cs), [RendererConsumerTests](../Rafter.IntegrationTests/Evaluation/RendererConsumerTests.cs), [renderer terminal verification](../../tools/evaluations/Verify-RendererTerminal.ps1), and [renderer measurement](../../tools/evaluations/Measure-Renderer.ps1). Full/Ansi/framework and file-app/project variants remain separate executable comparisons. |

All 43 files from the former `fixtures/` tree are retained in these groups. None was found to be unused: some are
exercised only by optional terminal/measurement tools. `Directory.Build.props`, `Directory.Build.targets`, and the
host consumer's `Directory.Packages.props` provide deliberate import boundaries for standalone execution.

The integration and Windows projects explicitly import [ConsumerWorkspace.targets](../build/ConsumerWorkspace.targets),
which copies these sources, production projects, examples, and root SDK/NuGet/package configuration into `Workspace/`
beside their executables. The unit project has no copied consumer workspace or ProcessProbe reference. The temporary consumer workspace
preserves their repository-relative paths. It excludes `bin/` and `obj/` output and does not consume old generated
files from the former locations. File-app directives and project references therefore work in either layout.

Package-only consumer sources are generated by [PackageConsumerTests](../Rafter.IntegrationTests/Consumers/PackageConsumerTests.cs)
and the [editor verification tool](../../tools/verification/Verify-Editor.ps1); they are not missing checked-in assets. Keep
generated packages, build output, and raw verification evidence outside this maintained asset tree's source files.

Run the root solution and consult the [documentation index](../../docs/README.md) for package and manual-tool checks.
The root solution does not discover the workflow asset's sample test project as another main test suite; integration
tests deliberately execute that project through Rafter.
